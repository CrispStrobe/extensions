# Prior binding and new publication

SOURCE candidate. The frozen operation specification declares its existing bind
role to the current host begin call, together with a held native own-descriptor
lookup of the private registry. Only a successful ticket and primitive String
NAME can request a one-shot prior-binding notice. The notice has no old body
payload. A host acknowledgement replaces recursive old-body inspection; a host
which declines retains the previous path. Original key coercion, registry lookup,
JSON parse/catch/fallback, assignment and completion ordering remain intact.

No-ticket or nonstring NAME calls keep the old path. Read/write/alias/escape roles
never declare discard. New-body completion still supplies its actual registry
body to existing guards; the host-born empty/JSON subset additionally requires a
fresh own-data registry join before final enrollment. Generic/custom publication
remains the old unqualified lane, not a new allocation certificate or transaction.

Run the complete existing host-operation and named-JSON protocol modules plus
`development/test-array-prior-binding.js`. Formatting and actual qualification
are pending; no public pin is adopted by this source proposal.

Host admission independently restricts this role to the actual five named-bind
constructors. That denial schema is never an allocation certificate: a correctly
named factory still needs its actual current call and separate native birth proof.
